## 3. Findings needing a decision

These depart from or fall outside the signed-off spec. Options and a
recommendation each; nothing has been changed.

**D-a. Row 17 starts at « ell », not « ella ».** The French « Elle est en
train… » becomes « Està preparant el sopar. » with `3sg`, no expressed subject
and no `subject_fem`, so `startingState` (`src/variants/combination.ts:131`)
selects « ell ». The approved eval base is `ella·present·estar·0·0`, and in the
app tapping « ella » pays for a call that returns the same Catalan. The
phase 1 schema has no field for the known gender of a dropped subject; only the
`subject_fem` assumption, which is meant for a guess.
Options: (1) let the phase 1 prompt emit `subject_fem` whenever the French
subject is feminine, and re-record; (2) add a `gender` field to `subject`,
which reopens the signed-off phase 1 schema; (3) accept it and document.
Recommendation: (1), plus a test pinning each eval row's `baseCombination` to
`startingState(recordedReply(n))`, which would have caught this.

**D-b. The validator does not check the pronoun and negation targets.**
`targetErrors` (`src/variants/check.ts:141`) checks person, tense and tournure
only, matching the spec's « Target realised » row. A reply for `negation: true`
that returns the sentence unchanged passes every check and is stored as the
negation. The same holds for `pronoun: true` with `object_direct` still there.
Recommendation: extend « Target realised »: negation on needs a `negation`
chunk, off needs none; pronoun on needs no `object_direct` chunk and a
`clitic` chunk. It is a spec change, so it wants a sign-off line.

**D-c. 3sg gender is not checked either.** `PERSON_OF` maps ell and ella to
`3sg`, so a reply in the wrong gender passes. Low impact (agreement errors
would show in the speaker review), but worth one line in the same sign-off.

**D-d. Exposure on first sight only.** `src/variants/store.ts:162` writes
`lookup` events once per variant row, whereas step 9 says « per linked ID that
the variant has and the previous state did not », each time. First-sight is
arguably the better rule (it stops repeated taps inflating exposure), but it
is a departure and should be recorded as a decision.

## 4. Bugs (confirmed in code)

**Status, 14 Nov: all six fixed on main, each with a test that failed
before its fix.** Bugs 2 and 5 share one change.

Ordered by severity. None touches FSRS or the taxonomy.

1. **An older tap can overwrite a newer one.**
   `src/variants/session.svelte.ts:222-247`. The tap aborts the previous
   controller, then awaits `findVariant` (a SHA-256 over the whole prompt plus
   an IndexedDB read) before creating its own. Tap an uncached combination,
   then a cached one inside that window: the second tap has nothing to abort,
   the first starts its call, and about 5 s later it settles over the second.
   « Revenir à ma phrase » in the same window has the same effect.
   Fix: a generation counter checked after every await, and memoise
   `variantPromptHash()`, which is constant per build.

2. **Reopening a phrase duplicates paid prefetch calls, and can double-count
   exposure.** `#inFlight` belongs to one session instance, but `dispose()`
   lets the prefetch run on. Leave and reopen a phrase while a prefetch call is
   in flight and the new session calls the same combination again: double
   cost, and two rows with the same `phraseId` and `comboKey`. The newer row
   has `seenAt: null`, so its `lookup` events are written a second time.
   Fix: a module-level in-flight map keyed by phrase and combination, or a
   re-check of the store before `put`.

3. **Import overwrites newer local rows.** `src/db/backup.ts:107` uses a blind
   `bulkPut`. Importing an older export resets `seenAt` (so events are written
   again) and would un-tombstone deleted phrases. Latent today, since no UI
   tombstones, but `sync.ts` implies last-writer-wins on `updatedAt`.

4. **« Réessayer » on the error card can do nothing.**
   `src/ui/screens/Phrase.svelte:139`. After a forced retry fails offline, the
   card's « Réessayer » calls `retry` without `force`, finds the cached
   `analysis_failed` row and returns it with no call.

5. **A cancelled tap stops the prefetch.** If the prefetch is sharing a tap's
   in-flight call and the user taps elsewhere, the shared promise resolves as
   `cancelled`, and `prefetch()` stops at its first `error`. Low severity:
   only lost warming.

6. **An unhandled rejection.** `Phrase.svelte:69`, `load().then(prefetch)` has
   no `catch`.

## 5. Accessibility and copy

French UI copy is correct byte for byte: U+202F before every : ; ! ? and
inside guillemets, typographic apostrophes, no hard-coded copy in components.
Panel buttons carry `aria-pressed` and `aria-disabled` and stay focusable;
targets are 44 px.

Gaps:

- **Sheets (chunk, settings, report)** declare `aria-modal` but do not trap
  Tab, do not make the page behind `inert`, and do not return focus to the
  opener on close (focus drops to `<body>`).
- **Catalan inside French strings is not marked.** The chunk caption
  « Verbe · vaig cantar » (`src/phrase/anatomy.ts:113`), the chunk button's
  `aria-label` (which overrides its inner `lang="ca"` span) and the Écouter
  label all make screen readers read Catalan with French phonetics.
- **Original `fr` is not run through `frenchProse`.** Variant French lines are,
  the original phrase's are not (`Phrase.svelte:160`, `Home.svelte:97`), so a
  straight ' from the model can reach the screen.
- The toggles announce their state twice (`aria-pressed` and « Oui »/« Non »
  text). A repeated identical reason line is not re-announced.
- Six tests contain a literal em-dash inside the no-em-dash assertion; writing
  the escape sequence (backslash u2014) keeps the rule literal.

## 6. Security and privacy

The key stays in `localStorage`, travels only in the `x-api-key` header to
`api.anthropic.com`, is never logged, and is absent from git history (only a
test placeholder). One exposure to write down: on GitHub Pages with no custom
domain, the origin is the whole `snewby.github.io`, so any other Pages site of
the account can read the key, and there is no Content-Security-Policy. Options:
a custom subdomain for this app, or a CSP meta tag limiting `connect-src` to
the API, or both.

## 7. Maintainability

- The phrase and variant pipelines duplicate `summedUsage`, `linkedIds`, the
  lookup-event builder, the current-row filter, the `fail` helper and the
  two-attempt loop (`src/phrase/store.ts`, `src/variants/store.ts`,
  `src/api/anthropic.ts`, `src/variants/client.ts`). Worth one shared module
  before phase 4 adds a third caller.
- `session.svelte.ts` (360 lines) mixes tap orchestration, prefetch and
  display; pulling the request and abort logic out would make bug 1's fix
  testable on its own.
- Small single-source leaks: `ContrastStatus` declared three times; the
  tournure list written by hand in `axes.ts` and `variants/prompt.ts`; the
  acabar de reason copy restates `ALLOWED_TENSES`.
