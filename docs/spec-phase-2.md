# francais-catalan: spec, phase 2 (Variations)

Oct 22, 2026 · @Sean

## Scope

Phase 2 lets the learner vary a translated sentence by person, tense, tournure, object pronoun and negation, one tap at a time, and see what changed and why, with every explanation authored and every variant checked by code. Signed off by Sean on 22 Oct 2026, all seven sections. Written against the plan doc (rev 25) and the phases 0 and 1 spec.

Builds on phase 1 unchanged: `PHRASE_SCHEMA`, computed spans, the closed ID vocabulary, the one-retry rule, the failure states and the `phrases` store. Nothing in the signed-off phase 1 schema changes.

| In phase 2 | Not in phase 2 |
| --- | --- |
| Variation panel on the Phrase screen: « Qui ? », « Quand ? », « Tournure », « Transformer » | Saving variants to the carnet, and review cards from variants (phase 4) |
| Rings on changed chunks and « Ce qui a changé » notes | The full notion sheet behind « Voir la notion » (phase 3; the phase 1 chunk sheet is reused) |
| `data/variation-notes.json`, about 15 authored switch notes | Subordinate-clause variation, imperative and subjunctive as targets |
| Variant cache, validation and eval | Prefetch, unless the 2 s target is missed |

The axes and values were decided on 21 Oct: 7 persons (jo, tu, ell, ella, nosaltres, vosaltres, ells); 6 tenses (présent, passé « ahir », passé « avui », imparfait, futur, conditionnel); 3 tournures (haver de, acabar de, estar + gérondif); 2 transforms (object to pronoun, negation).

## Schema and data

Each tap sends the original sentence plus a full target combination and gets back either a variant in the phase 1 shape, with a French translation, or a closed `not_applicable` reason; no prose.

### Request (built by the app)

```json
{
  "base": { "ca": "Ahir vaig comprar el pa al mercat.", "chunks": ["…phase 1 chunks…"] },
  "target": { "person": "ella", "tense": "avui", "tournure": "none", "pronoun": false, "negation": false },
  "timeWord": "Avui"
}
```

The request always starts from the original sentence, never from the previous variant, so a combination gives the same result whatever path led to it. `timeWord` comes from the time-word table below: a word, `drop`, or absent when the base has no time chunk.

### Response (`VARIANT_SCHEMA`, generated by `gen-schema`)

| Field | Type | Rule |
| --- | --- | --- |
| `status` | enum `ok not_applicable` | Exactly one of the two shapes below |
| `ca`, `subject`, `assumptions`, `chunks` | as `PHRASE_SCHEMA` | Present when `ok`; same validation as phase 1 |
| `fr` | string | Present when `ok`. A plain French translation of the variant, e.g. « Aujourd’hui, elle a acheté le pain au marché. » Never grammar commentary |
| `reason` | enum `aspect_incompatible subordinate_affected no_pronoun_form other` | Present when `not_applicable`. French text lives in `fr.ts` |

### Starting state (derived, no call)

The panel's selected buttons and greyed axes come from the phase 1 reply.

| Tournure | Tournure ID on the verb chunk, else Aucune | As Quand ? |
| Pronom | An `object_direct` chunk exists | No `object_direct` chunk |
| Négation | A `negation` chunk exists: starts at « Oui » | No verb chunk |

| Tournure | Allowed tenses |
| --- | --- |

### Time-word table

| Tense | Word |
| --- | --- |
| Passé « ahir » | Ahir |
| Passé « avui » | Avui |
| Imparfait | Abans |
| Futur | Demà |
| Présent, conditionnel | none: the time chunk is dropped |

Replace only: the word replaces an existing `time` chunk; a base with no `time` chunk never gets one. The word is sent only when the target tense differs from the original sentence's; otherwise timeWord is absent and the time chunk stays as it is (decided 22 Oct, e.g. row 6 « Hi vas demà ? » keeps « demà » on a person change).

### Switch notes (`data/variation-notes.json`)

Keyed by taxonomy ID, value a keyed map like glosses: `{ "VERB.perf.present": { "fr": "…" } }`. One or two French sentences on why the sentence changed when switching to that notion. `validate-ids` covers the keys; a test fails if any of the 15 IDs below lacks an entry.

- Tenses: `VERB.ind.present`, `VERB.ind.passat_perifrastic`, `VERB.perf.present`, `VERB.ind.imperfet`, `VERB.ind.futur`, `VERB.ind.condicional`
- Tournures: `VERB.mod.obligacio`, `VERB.perifrasi.acabar_de`, `VERB.perifrasi.progressiva`
- Pronoun swap: `PRON.feble.cd_3a`, `PRON.feble.en`, `PRON.feble.ho`, `PRON.feble.forma_alomorfs` (elision, « l'he comprat »)
- Others: `NEG.simple.no`, `PRON.fort.subjecte`

The 15 notes are drafted as the first phase 2 task and approved by Sean before the eval runs. The taxonomy and its schema stay untouched.

Approved by Sean on 22 Oct, all 15, checked against each leaf's notes and contrast\_fr. This is the text of data/variation-notes.json, value fr per ID.

| Taxonomy ID | fr |
| --- | --- |
| VERB.ind.present | Au présent, une seule forme porte la personne et le temps, en -o à la première personne : canto. Le mot de temps de la phrase disparaît. |
| VERB.ind.passat\_perifrastic | Pour un passé raconté, hier ou avant, le catalan parlé prend anar au présent suivi de l’infinitif : vaig cantar. Le sens est « j’ai chanté », pas « je vais chanter ». |
| VERB.perf.present | Quand la période inclut le présent (avui, aquest matí), le catalan prend haver suivi du participe : he cantat. Pour hier, il passerait au passé périphrastique. |
| VERB.ind.imperfet | L’imparfait décrit une habitude ou un arrière-plan passé, comme en français. Au premier groupe : -ava, -aves, -ava, -àvem, -àveu, -aven. |
| VERB.ind.futur | Le futur se forme sur l’infinitif, comme en français : cantaré. Sans futur proche avec anar, il traduit aussi « je vais chanter ». |
| VERB.ind.condicional | Le conditionnel se forme sur le radical du futur, comme en français : cantaria sur cantaré. Le mot de temps de la phrase disparaît. |
| VERB.mod.obligacio | haver de suivi de l’infinitif dit l’obligation : seul haver se conjugue, he de marxar. Il couvre « devoir » et souvent « il faut ». |
| VERB.perifrasi.acabar\_de | acabar de suivi de l’infinitif veut dire « venir de », pas « finir de » : acabo d’arribar, je viens d’arriver. Il ne se combine ici qu’avec le présent et l’imparfait. |
| VERB.perifrasi.progressiva | estar suivi du gérondif marque une action en cours, comme « être en train de » : estic parlant. Le catalan le réserve à ce qui se déroule vraiment ; ailleurs, le présent suffit. |
| PRON.feble.cd\_3a | Le complément direct devient un pronom faible devant le verbe conjugué, accordé avec le nom repris : el, la, els, les. |
| PRON.feble.en | Un partitif ou un complément en de devient en, devant le verbe : no en tinc gaires. Sa forme varie : en, n’, ne, -ne. |
| PRON.feble.ho | Une idée ou une phrase entière devient ho, jamais el : ho sé. Le français dit « le » dans les deux cas. |
| PRON.feble.forma\_alomorfs | Le pronom change de forme selon les sons voisins : devant une voyelle ou un h, el devient l’, l’he cantat. Un même pronom peut avoir jusqu’à quatre formes. |
| NEG.simple.no | no suffit seul, placé devant le verbe et ses pronoms : no ho sé. Pas de second élément comme « pas ». |
| PRON.fort.subjecte | Seule la terminaison du verbe change : le pronom sujet reste sous-entendu, puisque la désinence dit qui agit. On ne l’exprime que pour contraster. |

## Pipeline, validation, storage

One call per uncached tap, validated by code before it is shown or stored; one retry, then the previous state stays on screen with a retry offer.

### Steps

1. **Tap on a greyed button**: show its French reason under the panel; nothing else happens.
2. **Target**: the current combination with the tapped value changed. If it equals the original sentence's state, show the original from `phrases`, no call.
3. **Cache lookup** in `variants` by `phraseId`, combination key, schema version, model and `promptHash`. A hit shows at once.
4. **Call**: the same cached system prefix as phase 1 (taxonomy vocabulary plus both sets of instructions, so the cache is shared), the request above as the only dynamic content, structured outputs, 20 s timeout. A new tap during a call aborts it; the latest tap wins.
5. **Validate** (next table). `not_applicable` is a valid reply.
6. **Retry once** on a failed validation. Not a loop.
7. **Second failure**: nothing is stored, the previous state stays, and an inline line « Variante indisponible. » with Réessayer appears under the panel. The button is not greyed.
8. **Store** the reply in `variants`, `ok` or `not_applicable`.
9. **Record exposure**: one `lookup` event per linked ID that the variant has and the previous state did not. `EVIDENCE_EFFECTS` is unchanged.

### Validation

| Check | Rule |
| --- | --- |
| Phase 1 checks | Ajv against `VARIANT_SCHEMA`; spans derived; chunks in order; uncovered text only whitespace or punctuation; `unlinked` exactly when `ids` is empty |
| Only expected chunks changed | Compared with the original sentence. A chunk counts as changed when its role appears in only one of the two, or its text differs. Every changed role must be allowed by an axis that differs from the original (table below) |
| Time word | When `timeWord` is a word, the `time` chunk's text equals it; when `drop`, no `time` chunk; when absent, the `time` chunk is unchanged or there is none |
| Target realised | The verb chunk carries the tense and tournure IDs of the target; `subject.person` matches the target person |
| French line | `fr` present and non-empty when `ok` |

| Axis | Roles it may change |
| --- | --- |
| Person | `subject`, `verb`, `clitic` (reflexives: « em vaig equivocar » to « es va equivocar »), `complement` (agreement: « cansat » to « cansada ») |
| Tense | `verb`, `time`, `clitic` (elision: « el vaig comprar » to « l'he comprat ») |
| Tournure | `verb`, `clitic` (« l'he de comprar ») |
| Pronoun | `object_direct` (removed), `clitic` (added), `verb` (attached elision) |
| Negation | `negation` |

### Store (`catala-v2`)

| Store | Row |
| --- | --- |
| `variants` | `id`, `phraseId`, `comboKey`, `status`, `fr`, `ca`, `subject`, `assumptions`, `chunks` (with spans), `reason`, `model`, `schemaVersion`, `promptHash`, `usage`, `latencyMs`, plus the sync fields |

`comboKey` is `person·tense·tournure·pronoun·negation`, e.g. `ella·avui·none·0·0`. A tombstoned phrase tombstones its variants. Export and import include the store.

### Failure states

The phase 1 table applies to variant calls, shown as one inline line under the panel instead of replacing the screen; the sentence and anatomy stay as they were. Offline, cached variants still open; an uncached tap shows « Pas de connexion. ».

Model: whichever the variant eval picks, which may differ from the phase 1 model. CLAUDE.md gets a separate variant model line in the commit that records the choice.

### Running it

1. **Round 1**: both models, one run each. Replies failing the code checks are scored out before review.
2. **Review sheet**: renderings deduplicated across models, one card per combination, model hidden. The speaker marks the Catalan « naturel », « correct mais peu naturel » or « faux ». Sean marks each French line « fidèle » or « inexact ».
3. **Round 2**: both models, two more runs; only unjudged renderings go for review.
4. **Score**: `npm run eval:variants` replays recordings offline against the verdicts. `npm run eval:variants:record -- --model <id> --runs <n>` is the only paid step and never runs in CI.

If phase 1 picks Haiku 5.5, only Haiku runs and the floors decide pass or fail.

### Floors

Counted per model over 3 runs of every combination.

| Measure | Floor |
| --- | --- |
| Valid after the one retry: schema, spans, only expected chunks changed, time word, target realised | 100% |
| Catalan accepted | at least 95%, and no combination « faux » in 2 of its 3 runs |
| French line « fidèle » | at least 95% |
| `not_applicable` on every trap | in at least 2 of 3 runs for each trap |
| `not_applicable` where not expected | at most 3% of non-trap combinations |
| Padded links | at most 3% of all links |
| Latency, warm, 90th percentile | at most 8 s (floor); 2 s is the target, and a miss adds prefetch rather than failing |

Selection as in phase 1: the most « naturel » wins among models clearing every floor; cost breaks only an exact tie. If none clears, phase 2 stops and the floors go back to Sean. The report is `docs/variant-eval.md`.

## Acceptance criteria

Phase 2 closes only when every box is ticked by a test, a script or a CI run, never by use; the closing commit updates `TASKS.md` in the same commit.

Content and model

- [ ] `data/variation-notes.json` has an approved entry for each of the 15 IDs; `validate-ids` covers it; a test fails on a missing entry.
- [ ] The variant combination list is approved and recorded for each candidate.
- [ ] `docs/variant-eval.md` shows every floor per model, warm and cold cost, latency against 2 s and 8 s, and the choice; CLAUDE.md's variant model line matches.
- [ ] The chosen model's recordings pass `npm run eval:variants` offline, and CI runs it.

Schema and pipeline

- [ ] `VARIANT_SCHEMA` is generated by `gen-schema`; the hand-edit test covers it.
- [ ] Unit tests from recorded replies: a change outside the allowed roles fails; agreement and reflexive clitics pass for person; elision passes for tense and pronoun; wrong or missing time word fails; `drop` with a time chunk left fails; a base without a time chunk gets none.
- [ ] Starting state: each of the nine IDs selects its button; rows 8 and 22 grey « Quand ? » and « Tournure »; no `object_direct` greys the pronoun toggle; row 12 starts negation at « Oui ».
- [ ] Combination table: acabar de greys four tenses and those tenses grey acabar de; tapping a greyed button makes no call.
- [ ] Two paths to the same combination make one call; the original combination makes none.
- [ ] Retry exactly once; after two failures nothing is stored and the previous state stays.
- [ ] `not_applicable` is stored and greys the button on reopen with no call.
- [ ] A variant writes `lookup` events only for IDs new since the previous state; no FSRS change.
- [ ] `variants` rows carry a UUID and the sync fields; export and import round-trip them; a tombstoned phrase tombstones its variants.

Screen

- [ ] Rings mark exactly the chunks that differ from the previous state; « Revenir à ma phrase » restores the original with no call and clears rings and notes.
- [ ] « Ce qui a changé » shows one card per introduced notion, with the switch note where one exists, else `contrast_fr.note`.
- [ ] While waiting, the tapped button has a spinner and nothing else moves; a second tap aborts the first.
- [ ] Each reason in the copy table renders from a stubbed case; greyed buttons stay focusable with `aria-disabled`.
- [ ] UI copy test passes for every new `fr.ts` string; no English on screen.
- [ ] Playwright at 390 × 844: the pinned card and at least the first panel row are visible together; no horizontal scroll; targets at least 44 px.
